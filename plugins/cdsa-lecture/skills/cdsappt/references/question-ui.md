# 선택형 질문 창

사용자가 강의 내용과 자료를 주면 먼저 읽고 이미 확정된 정보를 추출한다. 사용자에게 물어야 하는 모든 질문은 네이티브 질문 도구로 별도 창을 띄운다. 선택형·직접 입력·누락 정보 확인·추가 변경 전 확인 모두 같은 원칙을 적용한다. 채팅 본문에 질문이나 번호 목록을 적어 답변을 요구하지 않는다. 질문할 필요가 없으면 창을 만들지 않는다.

## 도구 사용

- 현재 환경에 노출된 네이티브 질문 도구를 사용한다. 예: `functions.request_user_input`, 또는 해당 호스트가 제공하는 비동기형 `functions.request_user_input_async`. 실제 도구의 스키마에 맞춰 질문 맥락과 짧고 구별되는 선택지 2~3개를 넣는다. 기본 선택은 제출된 답변이 아니다.
- 한 번에 1~3개의 관련 질문만 묶는다. 가장 적합한 선택지를 첫 번째에 놓고 필요한 경우 '(추천)'을 붙인다. UI가 직접 입력을 제공하므로 '기타' 선택지를 중복 추가하지 않는다.
- 기관의 정확한 이름처럼 선택지를 만들 근거가 없는 정보는 options를 생략한 직접 입력 질문으로 받는다. 기관명·교육 시간을 임의의 후보로 지어내지 않는다. 이 도구로 파일 업로드나 스크린샷을 요청하지 않는다.
- 질문 도구는 현재 모드에서 실제로 사용 가능한 경우에만 해당 도구의 스키마와 지침에 맞춰 호출한다.
- 질문 도구가 제공되지 않는 환경에서는 채팅 질문으로 우회하지 않는다. 질문 창을 사용할 수 없다는 기능 제약만 알리고 답변에 의존하는 작업은 진행하지 않는다. 독립적인 작업은 계속할 수 있다. 창을 띄우지 못했는데 띄웠다고 말하지 않는다.
- 도구가 지원하지 않는 파일 업로드는 질문 창으로 요구하지 않는다. 필요한 첨부가 없으면 그 제약을 설명하며, 지원되는 파일 첨부 UI가 있을 때 해당 기능을 이용한다.

## 질문 내용

선택지는 받은 커리큘럼·대상·기관 업무에 맞춰 만든다. 예를 들어 표지 분위기가 미확정인 시설 데이터 교육에서는 '현장과 풍경이 어우러진 차분한 장면', '실제 업무를 보여주는 사실적인 장면', '부드러운 일러스트 장면'처럼 표현한다. 이것은 질문 구성 예시이며 모든 교육에 반복하는 고정 목록이 아니다.

사용자가 이미 답했거나 '알아서'라고 위임한 항목은 다시 묻지 않는다. 표지 질문 전에 실제 기관 업무와 교육 내용부터 파악한다. 희망 장수, 팔레트, 마스터 변경 등을 기본 질문으로 추가하지 않는다.

답변 대기 중에는 그 답변에 의존하지 않는 자료 검색·본문 작업을 진행한다. 실제 응답이 도착하면 request.json의 answers.value에 실제 선택 또는 직접 입력한 답변을 반영한다. 별도 근거 문장 작성은 요구하지 않는다. 필수 정보는 응답 전에 추측하거나 시간 경과를 동의로 간주하지 않는다. 제작 검증 통과를 위한 형식적인 승인 질문은 만들지 않는다.


## 답변 후 실행

- 사용자가 직전 질문이나 제안을 승인했으면 같은 내용을 다시 확인하지 않고 제작을 이어간다.
- 필요한 정보가 충분하면 자료 회수·PPT 작성·검사를 바로 수행한다. 작업을 막는 누락 정보가 있을 때만 네이티브 질문 창을 사용한다.
- 승인 범위 밖의 변경이 필요하면 적용 전에 네이티브 질문 창으로 확인한다.
- 사용자가 플러그인 규칙 수정을 요청한 경우에는 해당 수정과 검증을 먼저 완료한다.
